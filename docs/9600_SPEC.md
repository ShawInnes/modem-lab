# Modem Lab — Future 9600 bit/s Specification

## Status and goal

Deferred design for a future V.32-style live modem profile. This document does not request implementation now.

Build incrementally so each checkpoint is playable: listen to the signals, watch the aligned graphs, exchange real decoded text, and inspect how the receiver learns and maintains a connection. Session recording and playback remain out of scope by user preference.

## Signaling target

Primary reference: [ITU-T V.32 (03/1993)](https://www.itu.int/rec/T-REC-V.32-199303-I), particularly line signals, scrambling, receiver conditioning, startup and retraining.

| Property | Current experimental 2400 bit/s profile | Future V.32-style 9600 bit/s profile |
| --- | --- | --- |
| Symbol rate | 600 symbols/s | 2400 symbols/s |
| Data bits per symbol | 4 | 4 |
| Carrier frequency | Caller 1200 Hz; answerer 2400 Hz | Both endpoints 1800 Hz |
| Direction separation | Separate frequency bands | Echo cancellation |
| Samples per symbol at 48 kHz | 80 | 20 |

9600 bit/s comes from sending four data bits per symbol at 2400 symbols/s. It is not 9600 baud. V.32 defines both nonredundant 16-state QAM and a 32-state trellis-coded alternative. The latter adds a redundant coding bit while retaining four information bits per symbol. Start with the standard's nonredundant mapping; treat trellis coding as a later enhancement.

## Required DSP work

### Pulse shaping and matched filtering

Replace abrupt rectangular symbol transitions with designed transmit pulse shaping and a corresponding receiver matched filter. Choose and document filter parameters against the V.32 spectrum requirements. Preserve filter history across processing blocks and account for filter delay in diagnostics and acquisition.

Simply reducing the existing symbol length from 80 to 20 samples is insufficient for a useful telephone-channel modem: abrupt transitions spread energy outside the usable band.

### Continuous timing and carrier tracking

Recover symbol timing, carrier phase and frequency from received audio, then track them continuously. The existing acquire-once, fixed-clock receiver is insufficient. Validate independent initial phases, fractional delays, carrier-frequency offsets and sample-clock mismatch; do not share the remote transmitter's timing or phase with the receiver.

### Adaptive equalization

Learn and compensate for channel distortion and intersymbol interference. Train with known conditioning sequences, then maintain adaptation during data where appropriate. Report convergence and residual decision error. Exercise the existing telephone filter and degraded line settings, rather than proving operation only on a flat channel.

### Echo cancellation

Both endpoints transmit in the same band. Estimate and subtract each endpoint's own echoed transmission from its received waveform before decoding the remote signal. A receiver may use its own transmitted samples as the cancellation reference, but must not access the remote transmitter's symbols or text.

The existing line model already supplies delayed local echo. Use it for initial validation, then consider richer echo paths if needed to exercise adaptation. Specify supported echo strength and delay ranges and ensure filter sizing remains practical at the supported maximum delay.

### Scrambling and character transport

Implement profile-specific scrambling and descrambling so idle and repeated text do not create the current repeating idle comb. Follow the V.32 coding and differential mapping rather than reusing the V.22bis mapping without review.

Define how terminal characters enter the synchronous bitstream and how framing is recovered. Document whether the first experimental release retains simplified raw 8N1 framing or implements the standard's referenced asynchronous conversion. Never forward text directly between endpoints.

### Training, rate negotiation and retraining

Design an audio-driven startup state machine that trains timing, carrier recovery, the equalizer and echo canceller before admitting payload. Preserve the audible dialing, ringing and pickup experience, while distinguishing those illustrative exchange sounds from modem protocol signaling.

Implement V.32-style rate exchange and 4800 bit/s fallback in the later protocol milestone. Missing or corrupted received training must prevent a false connection. Add loss detection, bounded startup failure and retraining after significant channel changes. Timers may enforce protocol intervals and timeouts, but elapsed time alone must not establish successful acquisition.

### Optional trellis coding

Add the standard's convolutional encoder, 32-state constellation and sequence decoder after the nonredundant path works. Demonstrate the reliability benefit with measured bit-error rates under controlled noise. Do not count the redundant bit as additional payload throughput.

## Workbench and diagnostics

Reuse audio streaming, terminals, Auto chat, line controls, aligned spectrogram history and the event inspector. Keep graphs and terminals adjacent so both remain visible together.

Extend receiver diagnostics with:

- Constellation before and after equalization, using clearly identified measurement points.
- Timing error, carrier phase/frequency tracking and lock status.
- Equalizer convergence, taps and residual symbol error.
- Received echo mixture, estimated echo and cancellation residual; quantify cancellation with a defined metric.
- Actual training, rate selection, data, carrier-loss and retraining stages.
- Measured error metrics in controlled tests; do not present decision confidence as a measured bit-error rate.

All graphs and lock indicators must derive from actual samples or receiver telemetry. Label units, normalization and processing delay. Bounded telemetry and plotting must not stall audio or DSP processing.

## Playable implementation checkpoints

1. **Improve the current 2400 mode.** Add pulse shaping, matched filtering and scrambling with repeatable acquisition. Demonstrate the resulting spectrum and reliable live text before moving to the higher symbol rate.
2. **One-way 9600 on a clean channel.** Implement the V.32 nonredundant constellation at 2400 symbols/s on an 1800 Hz carrier, with independently recovered timing and carrier. Enable either endpoint to act as the transmitter in this explicitly one-way experimental mode.
3. **One-way 9600 through the telephone channel.** Add trained adaptive equalization and verify operation with filtering, noise and fractional delay. Expose convergence in the workbench.
4. **Simultaneous two-way 9600.** Add adaptive echo cancellation and validate genuinely overlapping payload transmissions on the same carrier. Restore full-duplex terminals and Auto chat; alternating Auto chat alone is not proof of full-duplex performance.
5. **V.32-style startup and recovery.** Add conditioning sequences, rate negotiation, 4800 fallback, startup failures and retraining. Make the actual learning stages audible and inspectable.
6. **Optional trellis-coded 9600.** Add 32-state coding and decoding, compare error performance, and expose suitable decoder diagnostics.

Each checkpoint must remain runnable and explain its fidelity and limitations. Revisit this plan against the standard before implementation; it is a roadmap, not a complete interoperability specification.

## Verification and acceptance

- Validate transmitter mapping and receiver recovery independently, including known symbol/bit vectors and varied initial alignment.
- Test long actual decoded byte streams, idle-to-data transitions, framing boundaries, carrier loss and reacquisition.
- Verify arbitrary processing-block partitions preserve waveform continuity and equivalent decoded output.
- Exercise noise, telephone filtering, fractional propagation delay, frequency offsets and clock mismatch. Record the tested operating envelope rather than promising arbitrary degraded-line performance.
- For full duplex, send substantial independent payloads simultaneously in both directions with local echo present and confirm exact received bytes under the declared baseline conditions.
- Verify adaptation behavior after live line changes and expose unsuccessful recovery honestly.
- Confirm real-time throughput, bounded queues, responsive plots and uninterrupted audio at the existing 48 kHz engine rate. Optimize measured bottlenecks as necessary.
- Keep startup, payload release and receiver status driven by actual received evidence.

## Fidelity and scope

Initially label the profile **experimental V.32-style 9600 bit/s**. Document implemented signaling, shaping, scrambling, framing, training, adaptation and omissions. Internal loopback success does not establish hardware interoperability or standards compliance; either claim requires separate validation against an independent implementation or real modem.

V.32bis higher rates, V.34/V.90, compression, error-control protocols, physical telephone interfaces, recording and playback are outside this plan.
